# 1.0.3 本地受伤通道热修复（待用户手测）

新增：每次 DC 命中随包携带不可变的来源/载体位置、方向、尺寸、等级，以关卡代次和实体 UID 绑定。来源死亡或从最新快照消失后，仍可建立仅供原生受伤事件使用的不可见代理。250ms 未回执重发相同事件，已执行的原生事件只重发缓存回执，不重复扣血。

修正：旧逻辑在一次 3 秒回执超时后把 defense.flag 改名，后续 Hero 伤害继续被拦截，形成永久无敌。本次保留受伤门控；持续超时明确记录失败并切回真实 Hero（可按 F7 重试），不是原生战斗验收通过。先同步关卡代次再处理回执，避免过渡帧拒收。已经死亡的 DC 来源不再调用受击成功回调。正常受伤仍通过原生 PlayerHurtAtk，未使用直接扣血绕过护盾、弹反、无敌帧。

还做不到：本轮按用户要求没有启动或操作游戏；普通受击、击杀来源同帧受击、弹丸、陷阱、护盾破裂及切换角色后的实战效果均待用户验证。自动回到 Hero 是故障处置，不是最终目标的成功兜底；引发它的攻击仍属于未满足的验收条件。护盾与原生闪避无敌可能合法挡伤，不强制每次命中扣血。没有新增实战延迟数据。旧 ZIP 与 GitHub v1.0.3 标签保持不变，本次仅本地源码和目录内 DLL 更新，不发布新版本。

已有证据：2026-10-17T07:35:11.697567Z，Mage360/MagicBall 事件 1 正常回执 native_shield；07:35:12.094940Z Rat UID 607499 死亡，07:35:12.098940Z 同来源事件 2 发出但无 DEFENSE 回执。现场留下 defense_timeout_20261017_073515_086.flag；之后日志反复 incoming_quarantined。原始第一轮 combat_guest.csv 已被此前重启覆盖，无法追认缺失回执时的具体异常；“来源消失”与当时快照代码一致，是本次修复的明确竞态路径，不能冒充已读到那条原生异常。

检查：ICEY/DC Release 均 0 警告、0 错误；真实 DamageOrigin.cs 独立回归通过 3 种区域设置往返、命中后来源变化仍保留 13 字段身份、6 类非法数据拒收。九原文件 SHA256 9/9 一致。这些不等同游戏验收。

手测：先运行同目录 Stop-Playtest.cmd 结束旧会话，再运行 Run-Playtest.cmd 加载两侧新 DLL。旧会话内超时标记不删除；新会话重新开启原生受伤通道。重点检查停止闪避时的普通怪物受击反馈/生命与护盾变化，以及击杀怪物同帧遭到其攻击后，后续仍能受伤。若突然变成 Hero，请保留日志，视为通道失败而非通过。
